# Seller console UX pass — November 2026

Scope: `apps/admin` (seller console). Every route, API call and integration stays as it was; the changes are UI, copy, and one checklist link.

## What changed

| Area | Change |
|------|--------|
| Navigation (`lib/dashboard-nav.ts`, `components/admin-shell.tsx`) | Daily pages first (Overview, Orders, Checkout links, Products, Chats, Customers). Delivery, POS and the optional online store sit in their own visible group, and rarely used tools fold away. Phones get a bottom bar (Home · Orders · Links · Products · More). The drawer closes on Escape and locks page scroll while open. Page search also matches descriptions and opens folded groups. Touch targets are 44px, with `aria-current` and `aria-expanded` set. |
| Home (`components/dashboard-view.tsx`, `app/page.tsx`) | A "What needs you today" grid: payments to confirm, to pack, to book delivery, delivery problems. Sales by channel (links / store / POS). A newest-link card with Copy. The setup checklist marks the online store as optional. |
| Orders (`components/orders-manager.tsx`) | Each card has a plain-language status label and one primary next action. Payment proof and reference sit beside "Confirm payment". COD shows "Collect on delivery". Phone numbers are formatted and tappable. The tab is kept in the URL (`?tab=`). The rider dialog keeps focus inside, validates PH mobiles, keeps input when the server rejects it, and closes on Escape. |
| Checkout links (`components/checkout-links-manager.tsx`) | Products can be quick-added inside "New checkout link". Validation sits next to the field. The footer shows the total before delivery. Picks survive a failed create. |
| Automations (`components/automations-view.tsx`) | Message previews. A clear on/off state per message. SMS / email shown as "Live" vs "Not connected yet" — no sending is implied when there isn't any. |
| Products (`components/products-manager.tsx`) | Name, price and stock come first. Photo and description follow. Sale price, pre-orders, visibility and main product sit under **More options**. Errors appear next to each field, focus moves to the first problem, and input is never cleared. Saving shows a success card with **Make a checkout link** (`/checkout-links?product=<id>`). The photo picker is reachable by keyboard. Loading shows skeleton rows, and a failed load has a retry. Product cards wrap their actions on phones, and status reads Live / Hidden. `/products?new=1` opens the form directly. |
| Onboarding (`app/onboarding/page.tsx`) | Copy and focus tweaks. |
| Global (`app/globals.css`) | Visible focus ring on all controls (light/dark). Respects `prefers-reduced-motion`. Short `gk-rise` entrance for success panels. |
| Formatting (`lib/format-ph.ts` + tests) | PH mobile normalise/format/validate, `tel:` links, payment method labels (GCash, Maya, Cash on delivery…). Non-PH numbers pass through unchanged. |
| Data (`packages/db/src/queries/seller-today.ts`) | The "Add your first product" checklist step links to `/products?new=1`. |

## Needs backend or product decisions

1. **SMS / email sending.** Automations show "Not connected yet" until a live SMS provider is configured. Previews never claim delivery.
2. **Payment confirmation.** "Confirm payment" is still a manual check of the buyer's proof. Auto-confirmation needs PayMongo / GCash webhooks to set `paymentState=paid`.
3. **Delivery booking.** The "Book courier" path depends on the Lalamove stubs in `packages/services`. Until live keys exist, sellers should use "Assign own rider".
4. **Product create response.** The success card uses `product.id` from `POST /api/products` to deep-link the checkout link. If the API ever stops returning it, the card still shows but without that button.
5. **`tenant-dashboard.ts` checklist** still links to `/products`. Change it to `/products?new=1` if that checklist is still used.
6. **Product card actions** (Share link, Set as main, Sizes, Captions, Edit, Delete) — consider an overflow menu for the rarer actions once there's usage data.
