# Go-live checklist — providers that are built and waiting for keys

Everything below is coded and tested with mocks. Each one switches on when its secrets are set on
the Cloudflare Workers (`wrangler secret put NAME` for each Worker listed). Nothing else changes.
Check status any time in **ops.guma.one → Settings → Integrations** (shows configured / missing).

Never paste secret values into chat, docs or commits.

## 1. SMS — Semaphore (buyer updates, reminders, seller alerts, POS receipts)

| Secret | Workers | Notes |
|---|---|---|
| `SEMAPHORE_API_KEY` | admin, web | From semaphore.co → Account → API |
| `SEMAPHORE_SENDER_NAME` | admin, web | Optional. Your approved sender name (e.g. `GUMAKART`). Without it Semaphore uses its default |
| `SMS_OPT_OUT_SECRET` | admin, web | Already generated by `scripts/deploy-cloudflare.ps1`; must be the same on both |

Before: texts are logged as **"Not sent"** in Automate → Auto SMS and ops → SMS & opt-outs.
After: send one test order to your own phone; check Auto SMS shows **Sent**.

## 2. Email — Resend (signup codes, password resets)

| Secret | Workers | Notes |
|---|---|---|
| `RESEND_API_KEY` | admin, web, platform | resend.com → API keys |
| `EMAIL_FROM` | admin, web, platform | e.g. `Guma Kart <no-reply@guma.one>` — domain must be verified in Resend (DNS records in Cloudflare) |

Before: production refuses to send codes ("We couldn't send the email right now").

## 3. Online payments — PayMongo (GCash / Maya / QR Ph / card through PayMongo)

Waiting on: Guma One business + BIR registration, then PayMongo account activation.

| Secret | Workers | Notes |
|---|---|---|
| `PAYMONGO_SECRET_KEY` | web, admin | Live `sk_live_…` |
| `NEXT_PUBLIC_PAYMONGO_PUBLIC_KEY` | web | Live `pk_live_…` (build-time variable) |
| `PAYMONGO_WEBHOOK_SECRET` | web | From the webhook you create for `https://kart.guma.one/api/webhooks/paymongo` (events: `payment.paid`, `payment.failed`, `checkout_session.payment.paid`) |

Then per shop: ops → Tenants → shop → Payments mode → `paymongo` or `both`.
Until then sellers use **direct GCash/Maya** (buyer uploads proof, seller confirms) and COD — fully working.
Test: ₱1 per method (GCash, Maya, QR Ph, card) on a test shop, confirm the order turns Paid by itself.

## 4. Messenger & Instagram — Meta (Phase 13, ready-to-hook-up)

Waiting on: Meta business verification + app review (`pages_messaging`, `instagram_manage_messages`).
Secrets will be `META_APP_ID`, `META_APP_SECRET`, `META_VERIFY_TOKEN` (admin). Do not submit
documents that aren't real; use the actual Guma One registration papers.

## 5. BIR official receipts for POS (ready-to-turn-on, Phase 11)

Switch stays **off** until an accountant confirms the OR/SI format, numbering series and
X/Z reading layout for your registration. Until then receipts say "This is not an official receipt".
